# QualCloud

QualCloud is a unified cloud file manager and explorer application. It aggregates files from multiple backends: the QualCloud central API, Convex-native storage (KenyCloud), Notter, and SHRTL.

## Technology Stack

- **Framework**: Next.js 14 (App Router) & React 18
- **Language**: TypeScript & Node.js
- **Database & Backend Services**: [Convex](https://convex.dev) (realtime backend, DB queries, mutation handlers, file storage)
- **Authentication**: [Clerk](https://clerk.com) (handles auth flows, multi-tenancy, and organization-switching)
- **External Webhooks**: Synced using Svix signatures in Convex HTTP endpoints
- **Styling & UI**: Tailwind CSS 3, shadcn/ui, Lucide React (icons)
- **Tables & Forms**: TanStack Table v8 (`@tanstack/react-table`), React Hook Form, Zod (validation)
- **HTTP Client**: Axios with automatic Clerk token authorization injection

## Run & Build Commands

Commands are run using NPM.

| Command | Action |
| :--- | :--- |
| `npm run dev` | Runs the Next.js local development server |
| `npx convex dev` | Launches Convex local backend sync & development console |
| `npx convex codegen` | Generates TypeScript definitions from schema changes (`npm run prebuild`) |
| `npm run build` | Builds a production-ready application bundle |
| `npm run start`| Starts the built production build locally |
| `npm run lint` | Runs ESLint analysis for TypeScript rules verification |

## Key Coding Guidelines

### 1. Unified File Modeling (`FileDoc`)
The app integrates multiple file sources. Regardless of the API (QualCloud, Notter, SHRTL, or KenyCloud/Convex), all items must be normalized into the shared `FileDoc` structure (defined in [components.types.ts](file:///Z:/script/JS/QualCloud/src/config/types/components.types.ts)).
* Use mappings like `mapFile` and `mapFolder` in [api/files.ts](file:///Z:/script/JS/QualCloud/src/app/api/files.ts) to parse raw JSON payloads before supplying them to `file-browser.tsx`.

### 2. Localization & Multi-language Support
Hardcoded strings in user-facing elements are **not allowed**.
* Import `useTranslation` from `@/components/hooks/use-translation`.
* Retrieve translations using `t("my.translation.key")`.
* Maintain values in both [ru.json](file:///Z:/script/JS/QualCloud/src/config/i18n/translations/ru.json) and [en.json](file:///Z:/script/JS/QualCloud/src/config/i18n/translations/en.json). Russian (`ru`) serves as the fallback translation language.

### 3. Authentication & User Syncing
* User identity verification is powered by Clerk.
* The frontend synchronizes the current user to the backend via `useSyncBackendUser(user.id)`.
* On the backend, Clerk events (User creation, Organization membership) are received by Convex webhooks at `convex/http.ts` under `/clerk` path, which calls mutations in `convex/users.ts` to keep the Convex relational database tables in sync.

### 4. UI / UX & Design
* All interactive panels use Tailwind classes styled alongside the dark background gradient rules declared in `globals.css`.
* Follow smooth transitional animations (e.g. `transition-all duration-200`) on hovers and modal displays.
